Mobile Legibility Pass

Resizing the Translate controls, relocating Summary Mode, and repairing Live Translate's background — which is not merely too transparent, but has no background colour at all.

Scope Mobile layouts + design tokens Base main @ f17693f Data model unchanged Prompts 4

1Solution overview

Three items were reported as visual polish. Investigation of the running build shows only the first is purely cosmetic — the other two are defects with measurable failure conditions.

The three reported items

M1 Target-language dropdown and Translate button are oversized in the Translate tab.
M2 Summary Mode sits awkwardly and should be repositioned.
M3 Live Translate background is too transparent under a custom theme; text becomes hard to read.

Primary finding — M3 is not an opacity value that needs tuning

The Live Translate container is styled bg-surface. No --color-surface token exists in the @theme block, so Tailwind v4 emits no rule at all for that class — grep -c '\.bg-surface' against the compiled stylesheet returns 0. The element's computed style in the running build is background-color: rgba(0, 0, 0, 0) with backdrop-filter: none.

The panel is therefore fully transparent in every theme. It only becomes visible as a problem once a wallpaper is set, because until then the opaque page background sits directly behind it. There is no current opacity to reduce — one has to be introduced.

Goals

  • Recover vertical space in the Translate tab without shrinking the primary action below a comfortable touch target.
  • Give Live Translate a real, theme-aware surface that holds legible text over any wallpaper.
  • Make the accent colour used for translated output respond to the active theme instead of being hardcoded.

Non-goals

  • No change to desktop layouts beyond the shared token fixes needed for M3.
  • No redesign of the tab bar, the input card, or the output card.
  • No change to translation behaviour, storage, or API surface.

Tailwind v4 generates colour utilities only from tokens present in @theme. --color-panel is declared and resolves through to a per-theme value; --color-surface is not declared anywhere, so the utility silently does not exist.

2.3 Recommendation — split the accent token

The brand teal #006D77 is used two ways: as a fill behind white button text, and as text colour on dark panels. These pull in opposite directions, and no single value serves both.

CandidateWhite text on it
(buttons)		It as text on dark card
(Live Translate)		Verdict
#006D77 current6.08 AA2.71 failGood fill, unreadable as text
#0E8A964.12 near4.00 nearCompromise, fails both narrowly
#14A5B32.97 fail5.54 AAGood text, breaks buttons
#2DBECD2.24 fail7.35 AAARecommended as text-only token

Ratios are WCAG 2.1 relative-luminance contrast, computed against the dark theme's card colour rgb(21,31,50). The conclusion is that one token cannot do both jobs:

/* src/index.css — @theme */
--color-accent:      var(--accent);       /* fills: buttons, active states */
--color-accent-text: var(--accent-text);  /* accent-coloured TEXT on panels */

/* :root (light) */
--accent:      #006D77;
--accent-text: #006D77;   /* 6.08 on white card — no change needed */

/* :root[data-theme="dark"], .dark */
--accent:      #006D77;   /* unchanged — white button text stays 6.08 */
--accent-text: #2DBECD;   /* 7.35 on dark card */

Cyberpunk and industrial themes already define their own accents that pass as text — #FF0055 scores 4.88 on the cyberpunk card and #E67E22 scores 4.61 on the industrial card. For those two themes, --accent-text can simply inherit the theme accent. They fail today only because Live Translate hardcodes the teal rather than reading the token at all.

4.2 M1+M2 Recommended layout

Pair the language selector with Summary Mode on one row, and keep Translate full-width beneath it. This addresses both items together: the dropdown stops being full-bleed, and Summary Mode gains a natural home instead of a row of its own.

Option A — recommended

Paired row + full-width action

Language chip sizes to its content on the left; Summary Mode becomes a compact toggle-chip on the right. Translate keeps the full width and a 44px height.

146 px → 92 px. Saves 54 px and one row.

Option B — alternative

Single row, all three inline

Everything on one 44 px row. Maximum density, but Translate collapses to roughly 120 px wide and loses its visual weight as the primary action.

146 px → 44 px. Saves 102 px.

┌─────────────────────────────────────┐ │ ┌──────────────────┐ ┌──────────┐ │ │ │ 🇻🇳 Vietnamese ⌄ │ │ ◐ Summary│ │ 40px auto-width │ └──────────────────┘ └──────────┘ │ │ ┌─────────────────────────────────┐ │ │ │ 🔤 Translate │ │ 44px full width │ └─────────────────────────────────┘ │ └─────────────────────────────────────┘ = 92px

Option A — the recommended arrangement.

Why A over B. Translate is the primary action and sits in the thumb zone; a full-width target is the easier tap and the clearer affordance. Option B's extra 48 px is not worth demoting it. Both keep every target at or above the 44 px minimum.

4.3 M3 Live Translate surface

Introduce a real surface token, then set its opacity high enough that the wallpaper cannot materially shift the background luminance. The table below composites the dark card over a white wallpaper — the worst case established in A4.

Panel alphaCompositeWhite body textTeal #006D77 textAssessment
0.00 todayrgb(255,255,255)1.00 fail6.08Body text invisible
0.20rgb(208,210,214)1.51 fail4.02Desktop's current value
0.50rgb(138,143,153)3.25 near1.87 failWorst crossover point
0.85rgb(56,65,81)10.28 AAA1.69 failBody fine, accent fails
0.92 proposedrgb(40,49,66)13.06 AAA2.15 failBody solved; accent needs §2.3
1.00rgb(21,31,50)16.48 AAA2.71 failLoses the wallpaper entirely

Read the teal column, not just the white one

Contrast for the teal translation text is non-monotonic — it bottoms out at 1.69–1.87 around alpha 0.5–0.85, because the composite background passes through the text's own luminance. No opacity value rescues it. Raising alpha fixes body text; the translated line only becomes legible once it stops being hardcoded teal and starts reading --accent-text from §2.3.

Specified values

Opacity: 0.92, with backdrop-filter: blur(16px). This keeps a visible hint of the wallpaper — the reason someone set one — while holding body text at 13.06 against the worst-case bright image. Below roughly 0.85 the wallpaper starts driving the background luminance rather than the theme; at 1.00 the personalisation is invisible. 0.92 is the point where the surface still reads as glass but the text no longer depends on the image behind it.

/* src/index.css — @theme */
--color-surface: var(--surface-solid);

/* per theme, alongside the existing --bg-card */
:root                      { --surface-solid: rgba(255,255,255,0.94); }
:root[data-theme="dark"]   { --surface-solid: rgba(21,31,50,0.92);   }
:root[data-theme="cyberpunk"]  { --surface-solid: rgba(23,8,41,0.92); }
:root[data-theme="industrial"] { --surface-solid: rgba(43,49,56,0.92); }

/* TalkTabMobile.tsx — root container */
- className="… bg-surface shadow-sm border border-border-main …"
+ className="… bg-surface backdrop-blur-xl shadow-sm border border-border-main …"

/* translated-output line — stop hardcoding the light-mode accent */
- className="text-xl md:text-2xl font-semibold text-[#006D77] …"
+ className="text-xl md:text-2xl font-semibold text-accent-text …"

4.4 Related — the same defect on desktop

TalkTabDesktop.tsx applies bg-panel/20 when a wallpaper is active. Because --bg-card is itself 0.85 alpha in every dark theme, the effective opacity is 0.20 × 0.85 ≈ 0.17 — the second row of the table above, where white body text scores 1.51. It is the same class of bug and worth fixing in the same pass, but it is outside the mobile scope the request named. Prompt 4 covers it and can be dropped without affecting the others.

4.5 Acceptance thresholds

  • Body text in Live Translate: ≥ 7:1 against the composited surface over a white wallpaper, in all four themes.
  • Translated-output line: ≥ 4.5:1 under the same conditions.
  • Every interactive target in the Translate controls row: ≥ 44 × 44 px.
  • Translate controls block: ≤ 100 px tall at a 430 px viewport.
  • No horizontal overflow at 320 px width; language chip truncates rather than wrapping.

7Open questions

These affect the design and should not be settled by default.

  1. Layout — A or B? §4.2 recommends Option A. Confirm before Prompt 3; B is a small edit from A but not the reverse.
  2. Does "too large" mean footprint or type size? (A1) This spec assumes footprint. If the text itself reads too big, the fix is different and smaller.
  3. How often is Summary Mode used? (A2) If it is per-translation rather than occasional, it should stay adjacent to Translate rather than pairing with the language chip.
  4. Is 0.92 the right balance? It deliberately preserves a hint of wallpaper. If Live Translate should be fully solid for factory-floor readability, raise it to 1.00 — the contrast table shows what each value costs.
  5. Include Prompt 4? The desktop defect is real but outside the stated mobile scope.

Recommended next step

Run Prompt 1. It is small, unblocks Prompt 2, and its correctness is verifiable with a single grep against the compiled stylesheet. Prompt 3 can proceed in parallel once the Option A / B question above is answered.
